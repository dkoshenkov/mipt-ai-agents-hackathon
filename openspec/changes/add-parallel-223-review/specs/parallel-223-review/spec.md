## Purpose

Ветка проверки по 223-ФЗ собирает независимые ответы по одному Markdown-документу и возвращает вызывающей стороне заключение критика с информацией о полноте проверки.

## ADDED Requirements

### Requirement: Параллельный запуск включенных проверок

Система SHALL принимать Markdown и непустой список включенных проверок. Она SHALL один раз передать исходный документ каждому выбранному агенту и выполнять независимые вызовы конкурентно. Вызывающая сторона может запустить ветку без указания числа одновременных запросов.

#### Scenario: Состав проверок меняется между запусками

- **WHEN** в список добавлена независимая проверка и тестовый провайдер задерживает ответы
- **THEN** до получения первого ответа у провайдера есть несколько активных запросов, включая добавленную проверку. После их завершения у каждой выбранной проверки есть свой результат

#### Scenario: Недопустимые параметры

- **WHEN** Markdown пуст после удаления пробелов или список проверок пуст
- **THEN** вызывающая сторона получает ошибку до первого обращения к модели

### Requirement: Агрегация и один критик на ветку

Для разрешенного к отправке контекста система SHALL дождаться исхода каждой проверки и выполнить одну попытку обращения к модели критика. Агрегат SHALL содержать по одной записи на проверку в порядке входного списка с ее идентификатором и находками либо ошибкой. Возвращаемый результат SHALL отличать успешную проверку от неполной и от ошибки критика.

#### Scenario: Один агент завершился ошибкой

- **WHEN** часть агентов вернула ответы, а для другой проверки провайдер вернул HTTP 429
- **THEN** критик получает успешные ответы и сведения об ограничении со стороны провайдера в одном вызове, а результат ветки содержит заключение и отметку о неполной проверке

#### Scenario: Все агенты завершились успешно

- **WHEN** все агенты ответили, в том числе если их списки находок пусты
- **THEN** критик получает все ответы, а вызывающая сторона получает его заключение и признак полной проверки ветки

#### Scenario: Все агенты завершились ошибкой

- **WHEN** каждый агент вернул ошибку
- **THEN** критик получает сводку ошибок один раз, а результат указывает, что ни одна агентская проверка не состоялась

#### Scenario: Сбой критика

- **WHEN** одна проверка вернула находку с цитатами, другая получила HTTP 429, а критик завершился по тайм-ауту или вернул ответ неверного формата
- **THEN** вызывающий код получает отчет с ошибкой критика, той же находкой, ее ссылками на исходник и ошибкой другой проверки. Повторных обращений к моделям нет

### Requirement: Композиция стадий

Библиотека SHALL позволять вызывающему коду отдельно получить исходы проверок, агрегировать их с привязкой к исходнику и вызвать критика. Вызывающий код SHALL иметь доступ к одному и тому же агрегату в обеих ветках обработки ответа критика.

#### Scenario: Сценарий участника команды

- **WHEN** автор добавляет проверку в список и в своей функции обрабатывает успешный ответ и ошибку критика через `match`
- **THEN** обе ветки могут вернуть находку с исходными фрагментами. Добавление проверки и выбор следующего шага выполняются в коде сценария без изменения исполнителя

### Requirement: Ограничение внешних вызовов

Система SHALL передавать внешним моделям только открытые данные. Ограничение распространяется на агентов и критика.

#### Scenario: Открытость документа не подтверждена

- **WHEN** для документа с неизвестным или закрытым статусом выбран внешний провайдер
- **THEN** запуск с этим провайдером отклоняется до передачи данных

#### Scenario: Дополнительный контекст перед критиком

- **WHEN** проверки обработали открытый документ, а перед вызовом внешнего критика сценарий добавил материал с закрытым или неизвестным статусом
- **THEN** обращения к внешнему критику нет. Вызывающая сторона получает причину и уже собранный агрегат

### Requirement: Журнал выполнения по умолчанию

Система SHALL без дополнительной настройки записывать начало и исход ветки, каждого агентского вызова, агрегации и критика с общим идентификатором запуска.

#### Scenario: Восстановление пути по журналу

- **WHEN** пользователь запускает проверку со стандартными настройками
- **THEN** по журналу можно установить, какие агенты завершились, где возникла ошибка и когда был вызван критик. Тексты ТЗ, промптов, ответов и секреты в журнале отсутствуют
