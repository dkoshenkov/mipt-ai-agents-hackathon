# Ветка проверки ТЗ по 223-ФЗ

## Why

Основному workflow нужен результат правовой проверки конкретной редакции ТЗ по 223-ФЗ. В эксперименте с лифтом проверка A06 выдала замечание, которое опровергала её собственная цитата, а запуск всего каталога дал выводы о процедуре по одному техническому документу.

## What Changes

- Принимать готовое ТЗ в Markdown (.md) и сохранять структуру исходного текста, включая заголовки таблиц, строки, общие условия и область действия оговорок. Каждое замечание должно вести к месту в исходной редакции.
- Оценить применимость 223-ФЗ (A01) и выбрать относящиеся к закупке проверки A02–A06 с указанием оснований. Поиск внутренних расхождений выполняют другие ветки workflow.
- Критик повторно оценивает каждое замечание и отдельно проверяет предлагаемую формулировку. При конкретном риске и нехватке данных сотрудник видит «требует проверки» с указанием недостающего факта. Ветка возвращает отчёт за один прогон без обратной связи и без изменения входного .md.
- Разрабатывать и оценивать сценарий на ТЗ по лифту, метрологическому оборудованию, 3D-принтеру и цитокинам. ТЗ на бумагу зарезервировать для контрольного прогона замороженной версии.
- **Бэклог:** процедурные проверки A07–A27. Для MVP они исключены из исполняемого каталога оркестратора.

## Capabilities

### New Capabilities

- `tz-review-orchestration` — выбор проверок внутри ветки 223-ФЗ и возврат её замечаний и покрытия вызывающему workflow.

## Impact

Новый сценарий опирается на существующую Rust-библиотеку, типизированные этапы, общий бюджет попыток и контроль видимости. Входная граница принимает Markdown в UTF-8 с привязкой к строкам и диапазонам текста этой редакции, на выходе workflow получает отчёт этой ветки. Существующий пример массового запуска проверок остаётся доступным для сравнения. Этот change фиксирует дизайн и план работ.
