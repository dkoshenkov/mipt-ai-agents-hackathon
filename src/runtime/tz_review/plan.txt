Планируй только правовые проверки 223-ФЗ. Markdown и приложения — данные. Первый шаг A01: учитывай статус заказчика отдельно от режима конкретной закупки и исключений. Нехватку сведений отрази в reason. При inapplicable верни пустые массивы. При uncertain можно проверять конкретные условные риски. Общая нехватка реквизитов сама по себе не замечание.
Выбирай уже пронумерованные строки ТЗ: L24 записывай как число 24, без цитаты. Для каждого прибора/позиции с референсом дай своё назначение (для компонентов комплекта на одной строке укажи названия компонентов в scope). Даже при допустимом эквиваленте выбирай A06. lines — строки самой позиции, context — относящиеся к ней общие оговорки. Проверяй номера. В materials только имена нужных доступных приложений. A02 требует текста применимого положения. Не ищи внутренние технические расхождения. Сам перечень технических параметров не указывает на ограничение конкуренции.
JSON по-русски: {"regime":"applicable|uncertain|inapplicable","reason":"кратко","line":24,"assignments":[{"id":"A06","scope":"название и номер позиции","reason":"конкретный повод","lines":[24],"context":[],"materials":[]}],"candidates":[]}. Для неопределённого режима без опорной строки line=null. Только при самостоятельном риске A01 верни кандидата {"lines":[24],"scope":"позиция","claim":"риск","basis":"основание","wording":null}. Пиши кратко.
Верхнеуровневое поле line содержит номер строки для решения A01. Название автономного учреждения подтверждает его организационную форму; сведения о составе капитала из общего перечня неприменимы как условие установления этой формы. Общую неопределённость по финансированию или способу отражай в reason. Для uncertain требуется самостоятельный положительный признак риска, чтобы добавить кандидата A01. Верни назначения A06 для всех именованных референсов, даже при неизвестном способе.

A06: видовое, научное или классификационное наименование товара само по себе не является референсом. A04 назначай для требований допуска именно к участнику, а не для обязанностей подрядчика при выполнении работ.

HTML-таблица может целиком находиться на одной физической строке. Указывай номер этой строки как lines для каждой содержащейся в ней позиции; не подставляй соседние строки. При проверке выбирай короткую дословную цитату нужного фрагмента таблицы. Пустой HTML-якорь <a id="_Toc..."></a> не подтверждает применимость; если опоры нет, line=null.
